# Mailbox Pattern: Inbox & Outbox

## Overview

The mailbox pattern gives an agent a structured interface with the outside world. It consists of two directories inside the agent's folder:

- `agents/[your-name]/inbox/` — incoming tasks, files, and instructions from the outside world
- `agents/[your-name]/outbox/` — deliverables and output produced by the agent

Both directories are **git-tracked** — `.md` files in inbox and outbox are committed during inscription. Other file types are managed per human instruction (exclude large binaries or sensitive files as directed).

---

## Inbox

The inbox is how the outside world communicates tasks and content to you.

### When to check it

You do **not** proactively scan the inbox. You check it when your human explicitly directs you to. Typical triggers:

- *"Execute the task in your inbox."* — The inbox contains a text file with instructions. Read it; treat it as the task.
- *"There is a file in your inbox — [explanation of what to do with it]."* — The file itself is the material; the prompt explains the task.

### After processing

Move the processed item to `inbox/processed/YYYY-MM-DD/` (where the date is today's date), creating the date directory if it does not yet exist. This is your acknowledgment that the item has been handled and is no longer pending.

### Protocol

1. List the contents of `inbox/` to see what is pending.
2. Read the relevant item(s).
3. Execute as instructed — either by the prompt or by instructions within the file itself.
4. Move processed item(s) to `inbox/processed/YYYY-MM-DD/`, creating the date directory if it does not yet exist.
5. **Log it**: Write a log entry noting which inbox item was processed and what action was taken.

---

## Outbox

The outbox is where you leave deliverables — things you produce that are intended for external consumption or that need to persist beyond the chat.

### When to use the outbox (by default)

Use the outbox when:
- No specific output destination was given
- You were asked to *make a deliverable* of something
- The response is too long for the chat
- The output was generated by a script

### Filename convention

```
YYYY-MM-DD-<snake-case-topic>.md
```

Examples:
- `2026-03-27-research-results-constraint-theory.md`
- `2026-03-27-agentchan-post-draft.md`

Use a different filename or format only when explicitly instructed.

---

## Logging

After processing inbox items or creating outbox deliverables, include them in your log entry:

```markdown
- **Date**: [date]
- **Action**: [task description]
- **Result**: success
- **Details**:
  - Inbox: processed `[filename]` → moved to `inbox/processed/YYYY-MM-DD/`
  - Outbox: created `outbox/[outbox-filename]`
```

---

## Relationship to Modes

| Mode | Inbox/Outbox |
|------|-------------|
| **Task** | Fully in play — check inbox when directed, write to outbox as default output destination |
| **Pulse** | **Ignore** — unless your human explicitly says otherwise |
| **Dream** | **Ignore** — unless your human explicitly says otherwise |

---

## Directory Setup

These directories must exist before the mailbox pattern can be used. During genesis they are created automatically (see `genesis.md`). If they are missing in an existing agent, create them now:

- `agents/[your-name]/inbox/`
- `agents/[your-name]/inbox/processed/`
- `agents/[your-name]/outbox/`

Also create an **empty** `.gitignore` inside the agent's directory. The mailbox contents (`.md` files) are tracked by default. Add exclusions only when your human specifically instructs it (e.g., for large binaries or sensitive file types).
